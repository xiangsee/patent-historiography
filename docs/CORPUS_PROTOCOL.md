# 样本总体、归属与数据版本协议

## 三种不同的“企业全部专利”
1. **自主发明组合（originated）**：申请时企业集团或其受控研发单位所形成的发明，须界定共同发明和职务发明。
2. **技术控制组合（controlled）**：企业某历史时点通过专利权、排他许可或其他可证的权利安排控制的技术；许可不必然等于所有权。
3. **资产持有组合（owned_as_of）**：按特定日权属记录属于该企业及其符合标准的控制实体的专利权。

三种口径分别保存、分别报告，不能把今天名下的专利追溯成过去自主研发。

## 实体表
每个主体至少有：entity_id、法定名称、别名、国家/地区、身份有效期、控制关系、证据来源、信心与争议标记。历史重组和名字更换是有日期的事件，不是永久别名。

## 核心标识
source_id / entity_id / patent_record_id / application_number / publication_number / simple_family_id / extended_family_id / claim_id / event_id。保留原始提供方标识，不能强行把简单/扩展同族合并为一个键。

## 时间规则
- **priority_date**：可能最接近发明技术构想的可见起点，但不是实际发明日。
- **filing_date**：申请日。
- **publication_date**：向公众公开日；US B类授权公报日期不能回填为最初公开日。
- **grant_date**：授权日，可能显著迟于商业化。
- **recorded_on / effective_on**：权属登记与约定生效日期可能不一致。
- **knowledge_as_of_date**：历史叙事中当时可被外部观察者获知的时点。

## 数据抽取单
每次查询记录：数据提供方、版本/快照日、实际检索时间、查询表达式、申请人展开规则、时间范围、国家范围、文件类型、去重方法、总量、已知缺失、获取/发布许可。可复现脚本与摘要统计可以公开；受限原始数据不得上传。

## 质量与偏差
- 新近专利申请的公开滞后导致右删失；年份末端单独展示。
- 不同法域/时代的专利制度与分类变化降低横向可比性。
- 某公司大量使用商业秘密或开源，不代表缺少创新。
- 引用既有申请可能由审查员加入，不自动证明发明人学习关系。
- 没有在某库找到不等于不存在；数据库是可观测样本，不自动等于全集。

## 数据实现
详细数据契约见 schemas/；抽取、清洗、对账与核验依次建立，不能用两个示范专利替代母集。

## v0.4｜四种历史时间与数据缺失类型
- occurrence_time：真实技术或商业行为发生的时间或区间；通常无法仅靠专利日期确认。
- record_time：申请、登记、档案制作或会议纪要形成时间。
- disclosure_time：外部公众可以从公开材料获知的最早时间。
- narrative_time：史家选择的书/篇起点、终点、阶段锚点与解释理由；不能覆盖其他时间。
- 完整观察窗须提供scope_id、原始时间、换算规则、精度、来源与竞争起点，参见 [chronology-scope.schema.json](../schemas/chronology-scope.schema.json)。

数据缺失标记建议分开：not_observed、source_lost、date_unknown、not_public、not_applicable、zero_observed、no_patent_filed。只有独立来源才能证明最后一种；未检索到专利不等于没有发明。
