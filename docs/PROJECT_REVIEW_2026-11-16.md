# 《企业史记》阶段审计：回归项目原始目标
日期：2026-11-16。审计对象为截至v0.7的公开仓库、研究笔记及GitHub Issues。本文件是研究项目复盘，不是已核验的企业史全文。

## 一、最初的任务究竟是什么？
1. 素材：尽可能完整地使用某一家企业历史上的公开专利资料，而非挑选数件知名专利。
2. 问题：通过专利理解一家企业技术能力、组织演化、成功、错失及其行业历史，而不是写专利排行榜。
3. 方法：研究《史记》纪传体学术传统，梳理国内外专利史与企业史理论，将本纪、表、书、世家、列传结合。
4. 产出：可核查、有独立历史判断且普通读者愿意阅读的一部企业史。用户明确要求先把方法大致弄清，再开始第一篇。
5. 长期治理：公开GitHub沉淀资料、方法与修改历史，但仓库规模不是终极目标。

核心句：从长期专利数据发现一般企业史容易忽略的历史关系，再用纪传体组织成可信而有故事的企业发展史。

## 三、哪些成果确实服务最初目标？
- 五体各有独立历史功能，不是五种装饰性写作形式；本纪和其他四体应相互纠正。
- 区分技术发现、专利申请、公开、授权、产品化、许可及组织取得的时间，避免从今天倒推过去。
- Google—Overture小实验显著修正“Google一开始便技术与商业全面领先”的目的论故事，并发现未采用的技术路线也有历史意义。
- 公司财经披露、专利、司法资料和技术论文的交叉印证是企业史重要方法。
- 不把专利数据库中的空白视为创新不存在，不把档案取得失败视为历史事件不存在。

## 四、哪里开始跑偏？
1. 本应从整体专利母集识别历史转折，实际先从熟知的广告案例出发，不断增加个案技术法证，形成样本选择偏差。
2. 多轮围绕GoTo专利族与程序光盘展开，追踪档案、原件和多个公开版本；史料价值真实，但占据了对一家企业整体历史的研究时间。
3. 工具和数据结构增长快于真实的历史发现。脚本通过不等于专利全集存在，更不等于因果解释成立。
4. 史学与经济学经典还没有充分融合，局部技术细节便成为事实上的研究主线。
5. 缺乏检验公众读者能否从作品中真正获得新认识的明确标准。
6. 项目多个“下一轮”自动顺着最近发现的技术线索前进，没有强制追问其与最初目标的关联程度；这是执行管理上的失误。

## 五、修正而不抹去之前的成果
- 不删除已经完成的研究笔记、数据示例与证据卡。
- Google/Overture成为五体互见的局部检验样本，不自动代表Google的全部企业技术史。
- Issue #14程序光盘与#15申请版本谱系归入非阻塞支线，不再主导下一轮。没有用户授权，不自行关停、删除、付费或联系USPTO。
- 下一轮主线恢复：有限必要的史学原著与专利理论深读、企业长时段专利母集可行性、五体书级框架和有历史解释力的叙事。
- 新的细分Schema与研究支线须先证明对长期母集、重大历史命题或整书编纂有明显贡献。

## 六、以后如何衡量进展？
1. COVERAGE：真实企业是否有可复核的全球专利母集口径、申请人历史映射、年份/国别覆盖率及缺失记录？
2. DISCOVERY：是否有某一项由长期专利数据揭示，而非先从知名故事倒填的历史转折？有无竞争者和反证？
3. NARRATIVE：五体是否各自增加独立理解并互相纠错？读者是否在不需要专利专业知识的情况下读懂历史？
4. GOVERNANCE：只有当一份新证据改变了以上判断，才升级为新的主线任务。新增文件和Issue不直接计分。

结论：前八轮不是白走，而是方法积累过多、整体实证不足。重新恢复“完整企业专利历史→历史发现→五体互证→读者可理解的企业史”的工作主链。
