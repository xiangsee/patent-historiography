# 古典文本到现代企业史的史料批判规范

## 1. 区分“文本作为一手材料”和“文本中所述事件被证实”

一份《史记》电子原文，对“司马迁如何安排秦始皇本纪”是核心直接证据；但对数百年前某场事件，它可能汇集前代史书、口述传闻、作者选择与后人整理。事件仍需史料对读，不能标记为天然已确认事实。

同理：专利公报是某申请在某日**公开了某些文字与权利要求**的直接证据，而不是该技术已经被实际商业实施或拥有市场影响的直接证据；上市文件是公司当时**披露了某些陈述**的直接证据，不自动证明其经营判断客观正确。

## 2. 建议的source层次

- documentary_object：存在的具体版本、法域、来源和检索日期；
- original_event：被陈述的事件/行为/实际日期（可有争议）；
- embedded_statement：当事人在史料内说了什么、归谁署名；
- narrator_interpretation：编纂者如何剪裁、评论和归因；
- later_commentary：后代注释、校勘和解释，绝不能混入原典作者；
- modern_inference：本项目的数据推断或评论。

**Primary/Secondary/Context不是来源的永恒属性；要按claim_id及其被证命题确定该份史料发挥的作用。**

## 3. 版本分层

《史记》正文 / 司马迁“太史公曰” / 引用前代史料与说法 / 后代补篇 / 三家注（裴骃《集解》、司马贞《索隐》、张守节《正义》）/ 网络平台后加标题和注释。引用需要保存具体版本与层次。

专利证据对应：原始申请文件/公开版本/授权文本/审查意见/转让登记/数据库聚合/第三方评论/AI模型解释。相同号码的不同法律文档不能混为一个陈述来源。

## 4. 新增的五项核验字段

- date_as_reported：原文日期与历法；不可直接改写。
- date_normalized / calendar_system / date_precision：现代标准化与精度，附换算依据。
- period_scope：观察窗口开始、终止事件及为何这样截断。
- source_layer / evidence_role_for_claim：相对于哪条命题是一手证据、间接证据、解释性评论。
- alternative_reading：最强其他读法及文本版本争议。

## 5. 优先处理“可流传的漂亮故事”

《刺客列传》篇末主动纠正关于荆轲的若干传闻并交代叙述渠道；这提示我们的列传写作不能为了故事而编造实验室对话、人物心理、管理层密谈。来源不可确证的故事必须删除或明确降级。  
《六国年表》承认秦记不完整；意味着企业的历史专利母集也必须有缺失说明。  
《秦楚之际月表》与《太史公自序》范围不同；意味着时间线并非只要做一次ISO日期转换就没有解释问题。
